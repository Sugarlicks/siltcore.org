# SILT Core v0.2 Website Release Plan

**Status:** Pre-publication website branch

This branch prepares `siltcore.org` for the SILT Core v0.2 release. The public `main` branch should remain unchanged until the v0.2 reviewer gate is complete and the specification is ready to merge/tag.

## Required positioning change

The current site still reflects the v0.1 architecture and must not remain live when v0.2 is announced.

The v0.2 site should foreground:

> **Source → Standing → Presentation → evaluation at the encounter**

SILT Core should be described as a semantic architecture through which legal, customary, cultural, private, institutional and technical orders can become mutually legible at moments of encounter without requiring ontological collapse or surrender of their own Sources of authority.

## Remove or retire from current-facing copy

- universal `Status` framing;
- universal `Capacity` framing;
- “authority semantics for digital action” as the primary definition;
- the old question “in what capacity is this action being taken?” as the architectural centre;
- claims that v0.2 is merely being planned;
- references to the removed generic consent validator as current infrastructure;
- language implying SILT is principally a layer between attestation, policy and execution;
- old v0.1 primitive lists presented as current Core.

Historical v0.1 material may remain accessible where clearly labelled as historical.

## Public-facing v0.2 story

The landing page should communicate, in this order:

1. **The encounter problem:** different orders meet digital systems carrying meanings that existing identity/credential/authorisation stacks do not fully express.
2. **The SILT seam:** Source → Standing → Presentation → evaluation at the encounter.
3. **Plurality:** legibility does not require one ontology, universal verifier or compulsory recognition.
4. **Boundary:** authentication, credentials, keys, capabilities and runtime authorisation remain downstream operational machinery.
5. **Why now:** agentic commerce, institutional delegation, digital instruments and plural governance make the semantic gap increasingly consequential.
6. **Proof:** v0.2 has been pressure-tested across transferable instruments, credential-carried institutional Standing, plural/collective encounters and recursive AI delegation.
7. **Links:** canonical specification, repository, changelog, conformance material and release/DOI once published.

## Tone

The website should be concise and public-facing. It should not reproduce the full normative specification or collapse SILT into a product, identity stack or authorisation protocol.

Avoid claiming universal legal validity, compulsory recognition, certification, ontology resolution or law-engine behaviour.

## Release sequence

- Complete website copy on this branch.
- Run external reviewer gate against the full v0.2 release package.
- Apply any reviewer-driven editorial corrections.
- Merge SILT Core release branch to `main` and create `v0.2.0` tag.
- Merge this website branch to `main` at the same release point or immediately beforehand.
- Confirm `siltcore.org` displays v0.2 language before public announcement.
- Add DOI / archive link after Zenodo publication.

## Canonical source

Website language must remain subordinate to the canonical SILT Core v0.2 Semantic Architecture in:

`Sugarlicks/silt-identity-core/spec/v0.2/semantic-architecture.md`

The website is explanatory material, not a second specification.
