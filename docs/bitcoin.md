# Why This Matters for Bitcoin

Bitcoin is very good at one thing SILT Core deliberately does not try to replace: proving that a valid key authorised a transaction under Bitcoin's technical rules.

But cryptographic control is not the same thing as relational Standing or Authority.

A signer may be acting personally, as a trustee, as an institutional delegate, under a private agreement, or within a collective arrangement. The same key can be technically capable of signing while the semantic conditions surrounding that action differ materially.

SILT Core v0.2 provides a way to keep those distinctions legible without changing Bitcoin itself.

The relevant seam remains:

> Source → Standing → Presentation → evaluation at the encounter

A Participant may Present the minimum relevant projection of Standing for a particular Bitcoin-related encounter. One or more Profile Expressions may state the encounter-relevant conditions under which that Presentation, any claimed Authority, Consent, Reliance, Attribution or Obligation should be evaluated.

Bitcoin then remains what it is: an execution and settlement substrate.

SILT does not turn Bitcoin into a law engine, identity system or universal verifier. It preserves semantic context around an action where that context matters, while key management, transaction construction, signature verification, policy and execution remain in their native technical layers.

The distinction is simple but important:

**technical capability can move the asset; SILT helps make legible the relational conditions under which that movement is being presented and evaluated.**
